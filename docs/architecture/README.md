## Реализованные компоненты

- `MainWindow.xaml` и `App.xaml` — WPF-интерфейс на .NET 8: ввод URL, выбор папки, карточка видео, команды загрузки и журнал.
- `MainWindow.xaml.cs` — оркестратор: проверяет ввод, запускает `yt-dlp.exe` через `ProcessStartInfo.ArgumentList`, читает `stdout`/`stderr`, управляет состоянием окна и загружает обложку.
- `tools/yt-dlp.exe` — извлекает сведения и медиапотоки YouTube через основной и встроенный API-клиенты.
- `tools/deno.exe` — локально выполняет JavaScript-челленджи YouTube.
- `YoutubeCookies.cs` проверяет формат файла Netscape и отбирает записи для `youtube.com` и его поддоменов.
- `BrowserSession.cs` находит папки профилей Firefox, Chrome и Edge и хранит выбор пользователя в `%LOCALAPPDATA%\YoutubeDownloader\browser-session.json`.
- `tools/ffmpeg.exe` и `tools/ffprobe.exe` — объединяют видео и аудио и преобразуют аудио в MP3.
- `scripts/Get-Dependencies.ps1` — получает официальную сборку yt-dlp и FFmpeg для локальной разработки.
- Выбранная пользователем папка — конечное хранилище загруженных файлов.

## Интерфейсы и поток данных

1. Пользователь вводит HTTP(S)-ссылку и выбирает папку.
2. WPF передаёт команду оркестратору событий окна.
3. Оркестратор запускает локальный `yt-dlp.exe`, передавая каждый аргумент отдельно. Для HTTPS-ссылок YouTube оркестратор может передать выбранный профиль через `--cookies-from-browser` либо временную копию выбранного файла через `--cookies`. Временная копия удаляется после завершения или отмены процесса.
4. yt-dlp обращается к YouTube по HTTPS через клиенты `default,web_embedded`, передаёт JavaScript-челленджи Deno и при необходимости вызывает FFmpeg.
5. `stdout` и `stderr` отображаются в журнале; результат записывается напрямую в выбранную папку.

Внутреннего HTTP API, фоновой службы, базы данных и облачного бэкенда нет.

## Обработка сбоев

- Сетевые, фрагментные и extractor-запросы повторяются до 10 раз с экспоненциальной задержкой.
- Ошибки DNS и тайм-ауты преобразуются в понятные сообщения.
- Пользовательская отмена завершает дерево процесса и считается состоянием «Отменено», а не ошибкой yt-dlp.
- Полный вывод yt-dlp остаётся в экранном журнале; постоянного файла журнала пока нет.

## Ограничения и открытые вопросы

- Работа зависит от системного DNS, интернет-доступа и изменений YouTube.
- Выбор браузера действует до отключения сессии или выбора другого источника. Экспортированный файл используется до закрытия окна. Сохранённые настройки содержат только имя браузера и путь к профилю. Доступность ролика и действительность сессии определяет YouTube при запросе. [Решение о подключении браузера](decisions/0004-youtube-session-from-browser.md)
- Временная копия удаляется при штатном завершении операции, включая отмену и закрытие окна. При аварийном завершении приложения или ОС копия может остаться в системном каталоге временных файлов.
- Автоматического набора интеграционных тестов нет. Проверки выполняются вручную на публичных роликах без сохранения тестовых файлов.
- Инструменты из `publish/tools` обновляются независимо от WPF-сборки.
